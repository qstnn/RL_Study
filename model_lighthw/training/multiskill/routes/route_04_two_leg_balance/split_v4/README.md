### 本轮奖励变化

权重沿用D1：姿态/COM/支撑/净空/捕获为`3/5/10/8/10`，双轮/安静为`4/2`，悬空轮载荷/左右差为`−4/−2`，严格保持/恢复为`12/6`。只修改下列连续函数，保留旧档案行为：

| 变化 | 新设置与目的 |
|---|---|
| 姿态和COM过渡 | 使用`0.25 + 0.75×两前轮中较差的卸载程度`，前轮尚承载时保留25%引导；仍须指定后轮有承载 |
| 动态承载 | 总轮载由`≥0.65×体重`硬门改为`clip(总轮载/(0.65×体重),0,1)`；两后轮中较小载荷仍参与，腾空、错腿和单后轮引导为零 |
| 支撑和净空 | 不使用25%底值，仍按真实两前轮卸载程度计算，不能靠四轮停留拿满收益 |
| 捕获与双轮收益 | 同时乘低速度质量`exp(−(角速度/0.35)²−(COM速度/0.18)²)`；保持时再乘`exp(−(保持漂移/0.10)²)`，降低高速经过目标和滚走的收益 |
| 保持安静 | 保留双轮/姿态/COM条件，并加入上述连续漂移质量 |
| 保持漂移成本 | 从10cm之后才罚改为`min((漂移/0.10)²,4)`，在验收边界前提供反馈；其他阶段成本保持 |

这些函数提供的是训练引导；真正保持仍按1kHz严格门和连续计时判断。动态检查中的分段控制器不进入Actor动作路径，COM与轮载真值仍仅用于Critic/奖励/诊断。新增训练采样记录姿态误差、COM/角速度、双轮/平衡占比和保持漂移，均是每次更新末尾的当前环境统计，不是额外冻结评估或整轮均值。

## 历史奖励设计：baseline_v4与D1

连续项乘`dt=0.02s`，以下系数按秒理解。动作全部由Actor输出；没有参考动作注入、外力扶持、根速度重置、姿态强制跟踪器或物理限幅放宽。

| 项 | 权重 | 激活与含义 |
|---|---:|---|
| 姿态进度 | 4 | 转移/保持；`clip(1−最终目标角误差/目标倾角,0,1)`，四轮直立姿态为0 |
| COM进度 | 8 | 转移/保持；`clip(1−COM支撑线距离/0.45m,0,1)`，允许中间状态获得部分收益 |
| 指定承载×另一对卸载 | 8 | 两支撑轮均承载、总轮载≥0.65体重；另一对载荷下降才增加 |
| 双轮净空 | 6 | 两悬空轮最小净空/8cm，同时乘卸载与指定承载；3cm成功门不变 |
| 联合接近目标 | 8 | 承载×卸载×COM高斯(12cm)×最终姿态高斯(0.35rad)，避免仅倾身或挪轮拿满分 |
| 合格双轮支撑 | 4 | 真实双支撑，再乘上述COM/姿态质量；短暂抬轮不算成功 |
| 悬空对残余载荷 | −2 | 转移/保持；另一对载荷/体重，鼓励继续卸载 |
| 安静 | 2 | 保持时须双支撑及接近COM/姿态目标；恢复时须已严格保持且四轮接触 |
| 初始站稳/站姿 | 1 / 0.5 | 仅入场，保留任务开始能力 |
| 返回站姿/直立 | 1 / 2 | 仅返回/恢复，且此前已完成严格双腿保持 |
| 严格保持/严格恢复 | 12 / 6 | 沿用1kHz真实连续计时 |
| 首次保持/最终成功 | 20 / 40 | 一次性事件，不乘dt |
| 未完成保持/物理失败 | −8 / −20 | 前者保持窗口结束只扣一次；后者沿用碰撞/摔倒/漂移失败判据 |

`unload_diag_v1`只在任务引导项上做诊断改动：姿态/COM/指定承载/净空/组合接近目标的权重为`3/5/10/8/10`；悬空载荷改为两只轮中较大载荷的连续惩罚`−4`，新增左右载荷差惩罚`−2`。两只悬空轮的归一化载荷以每轮`0.25×体重`为1，任一轮仍接近原四轮承载水平时，姿态和COM进度门控为零。严格验收仍使用2N、3cm、12°、0.06m等原阈值。

保留小幅动作变化、扭矩、关节速度、轮速、饱和、漂移和时间成本。没有通过修改最终目标或放松判据提高成功率。COM距离按选定双轮的有限线段计算，不能靠侧移到无限支撑线外蒙混过关。

PPO保持32步rollout、5轮×4小批更新、LR起点1e−4、整批KL>0.03时恢复模型和完整Adam并减半LR；gamma从0.99改为0.995，以增加较晚保持/恢复收益的影响。Actor305/Critic88/动作16保持。算法遵循[标准PPO](https://arxiv.org/abs/1707.06347)，这些任务参数是待正式训练检验的工程选择。
