### 高附着摩擦系数的计算与修改

按真实机器人质量11.66811149 kg、被动拖车40 kg、拖车滚阻0.02、坡度θ、沿坡加速度a，平行坡面拖杆近似下：

```text
N_robot = m_robot g cosθ
T_cart = m_cart g sinθ + 0.02 m_cart g cosθ + (m_cart + ΣI_cart/r_cart²) a
F_robot = m_robot g sinθ + m_robot a + T_cart
μ_min = |F_robot| / N_robot
```

40 kg拖车的四个实心圆柱轮合计 `ΣI/r²=2 kg`。这部分提高拖杆加速需求；机器人自身轮转动惯量影响轴力矩，不能再次当成整机平动质量重复加到地面合力。

| 条件 | 整机纵向合力下限μ | 16边内接摩擦锥保守下限 |
|---|---:|---:|
| +25°/40 kg匀速 | 2.13344 | 2.17524 |
| +25°/40 kg、a=+0.3 m/s² | 2.28864 | 2.33348 |
| −20°/40 kg制动、a=−0.3 m/s² | 1.69284 | 1.72600 |
| 教师最严纠偏：+25°/40 kg、a=+0.6 m/s² | 2.44384 | 2.49172 |

扫描全部64许可条件，常规指令最严的是+25°/40 kg、0.3 m/s²起步。进一步覆盖教师0.6 m/s²纠偏，再乘1.20、按0.1向上取整：`ceil(2.49171984 × 1.20 × 10)/10 = 3.0`，实际余量 **20.40%**。前三姿态逐场景联合力/矩/96-48 Nm/每轮至少1 N约束的LP二分求解，下限同为约 **2.491720**，与整机保守界一致。

`scripts/settings.py` 是本研究摩擦系数的唯一声明源；机器人、拖车、地面静/动摩擦、QP和姿态LP统一3.0，组合方式`min`。`friction.json`保存计算，`friction_runtime.json`核对实际PhysX资产参数和USD地面材料。V5/V6历史配置和旧结果仍保留原值4，不回写历史证据。

这个下限依赖四轮接触、近似平行拖杆及准静态法向载荷；没有证明任意瞬态都不打滑，也不是实测轮胎/地面材料值。3.0下的旧Actor能力必须重新冻结验收；若实际μ需求超过配置，应先查姿态/动态卸载/横向内力，不能自动把参数抬回4。

### 与约0.7的传统爬坡估算如何比较

2026-10-20追加核对：用户确认40kg由拖车自己的轮子承重、坡度25°，以`tan25°`判断最小不滑动。`tan25°=0.46631`适用于滑块静止或车轮能提供相应制动力的情况；约0.7可视为在此基线上留余量。自由转动的无驱动/无刹车车轮可不打滑而向下滚，不能将“无滑移”直接等同“停在坡上”。当前URDF机器人11.6681 kg拖40 kg四轮无动力车，两者同时在25°坡上，且近似平行坡面的牵引杆不提供额外法向压载。

先只考虑机器人静止牵住未制动拖车、忽略滚阻和加速度：拖车牵引拉力为165.8354 N，机器人还要承担自身坡向重力48.3747 N，故驱动轮需要214.2101 N；除以机器人总法向力103.7398 N，得到μ下限2.06488。如果拖车各轮可以制动并自行承担其坡向重力，才可另按μ≥tan25°评估整体静止。

匀速时机器人四个驱动轮的总法向力为103.7398 N；自身爬坡48.3747 N、拖车爬坡165.8354 N、拖车滚阻7.1127 N，驱动轮需提供合计221.3228 N。因此μ下限为221.3228/103.7398=2.13344。拖车重量由自己的无动力轮支撑，不能把它的全部法向载荷直接加入机器人驱动轮的可用附着力。

若μ=0.7，现有理想模型下机器人最大纵向附着力72.6178 N，小于221.3228 N；平地拖40 kg的匀速下限则仅0.06856。空载或重量全部落在驱动轮上的背载爬25°坡，忽略其他阻力时下限为tan25°=0.46631。这些工况差异必须先统一，不能只比较摩擦系数数字。

若实际牵引结构向机器人传递显著法向载荷、拖车轮有驱动、实际机器人质量不同或拖车不在同一坡面，必须改写受力方程。当前μ=3.0只是使既定模型目标具有余量的研究参数，没有实测材料依据；若目标地面实测μ约0.7，应将实测值作为约束，重新评估目标和承载/驱动结构。本次仅核对解释，未再次修改摩擦参数或启动GPU。

## 4. G2：动态教师的实现与限制

依据[原论文](https://arxiv.org/pdf/1809.03557)的浮基动力学和滚动约束思路，使用 34 个变量：22 维广义加速度和 12 维接触力。详细论文边界见[一手资料核对](references/WBC_PRIMARY_SOURCES.md)。本原型不复现论文的完整 ZMP/步态规划，也不宣称论文证明了本机重拖能力。

- PhysX 提供 22×22 浮基质量矩阵、重力/科氏补偿、全身雅可比；用独立 URDF 模型逐步核对坐标和质量。根速度基点及连杆线速度雅可比均为刚体 COM。当前 API 质量矩阵不含 DOF armature，控制求解显式加回。
- 保留实际弹簧/阻尼拖杆，计算当前有符号三维外力。下坡允许拖车推机器人；不叠加理想刚杆约束或额外根推进力。
- 使用随构型迁移的几何接触矩阵 `A(q)v=0`，沿真实运动数值求导，约束 `A qdd + Adot v = -8 A v`。包含轮架/腿运动；不是简单指定 `wheel_speed=v/r`，也不是把轮固连材料点加速度设为零。
- 硬约束包括浮基动力学、滚动、内接摩擦锥、非负且至少 1 N 的预测法向力、轴力矩、原生动作可达范围、一步关节位置/轮速、根高度/牵引净高，以及局部线性化的 roll/pitch ±10.5°。COM 运动、车身姿态和腿姿态作为软任务。加速度数值界和局部姿态预测是明示研究约束，不等于真实硬件能力。
- 使用原 **50 Hz、20 ms 保持**的腿位置/轮速度接口。先将求解力矩反解为原生动作；腿/轮变化尺度1/0.5 Nm用作权重0.1的软平滑归一化。原硬变化限额在真实下坡QP反例中排除了原96/48Nm、μ3.0下的可行解，已取消该人工硬界；真实力矩/伺服可达界仍为硬约束。保存实际1kHz请求/施加力矩核对20ms保持偏差，不据软平滑推断硬件电流上升率。
- SLSQP 是离线研究求解器，不承诺实时运行。不可行、残差超限、模型交叉检查失败或接触估计失效，候选标失败；不放宽物理上限、不把回退 Actor 当成功教师。

**本轮μ=4历史短验发现：** 动力学接口和约束求解能够运行；最初接管版本约1.52/1.76 s丢失接触，加力矩变化界后约1.56/1.72 s仍失败（+25°/−20°，同坡静止/移动在起步前相同）。这些试验均不足3 s，尚未到达3 s起步时刻。它们说明必须先查清接管时的接触/力分配和位置伺服响应，不能称“完整教师已做成”。最终交付μ=3.0、含一步姿态/净高预测的短验另见[验证记录](results/2026-10-20_validation/README.md)。

**接触状态判断修正：** 新增`contact_state.py`。原单一50Hz瞬时法向力阈值在本机把有4个原生接触点、微米级间隙、平均载荷正常的毫秒冲量脉冲判成离地。现在联合最近20个1kHz样本的每轮平均法向力≥1N、最新原生接触点数>0、最小间隙≤0.1mm且穿入≤1mm判断。原完整行为协议的支撑率/姿态/漂移门槛不变；这是一项接触估计修正，不宣称解决WBC动态能力。

正式教师筛查：每个选中姿态，3 个观测噪声种子（43/44/45）×2 种槽位排列×4 工况；四工况为 +25°/−20°×静止/移动。任一试验失败就停止该姿态候选，不继续耗费剩余重复预算；只有同一姿态全部六次完整通过，才标 `teacher_screen_passed`。这是固定初态的初筛；初态扰动、接管力矩偏差审查和学生闭环仍是后续门，因此 `student_training_ready`、`ppo_ready` 保持 false。

## 5. G3/G4：随后怎样迁移和恢复 RL

以下是下一阶段实施规格，不是本入口已启动的训练：

1. 只把完整行为通过的回合纳入成功示范，失败轨迹单独留作诊断。每帧保存部署观测300、实际执行动作16、case、阶段、seed、episode、slot、checkpoint/源码SHA。教师真值速度、接触力、COM和拖杆力只能进独立诊断字段。
2. 阶段分为等待、起步、拖行、减速、2 s过渡、5 s保持；按 case/stage 均衡，按完整回合/种子划分训练和留出，禁止随机拆邻接帧制造伪泛化。保留原空载高速、15 kg背载及已有拖载成功数据，重建旧 legacy 单组缓存。
3. 学生仍是统一300→16网络，维持现有动作历史80列屏蔽。先做保守监督拟合和原Actor保持；离线动作MSE只诊断拟合，准入靠同一物理/原生接口下的闭环留出试验。需要修正学生访问状态时，教师标签也必须来自该访问状态，不能混入教师特权输入。
4. 学生覆盖原来成功的15项及新增重拖/下坡能力后，再恢复受控PPO。首批覆盖全部64条件，不先用只含重拖的小环境覆盖掉旧能力。保持冻结保护/KL上限，加入 case/stage 采样、分工况KL/优势/动作变化、真实机器人和拖车的有效运动转移统计。
5. 奖励研究以真实有符号拖行进度、完整停车协议、侧向速度/航向、支撑裕量和滑移为重点；沿用真实失败/碰撞/牵引净高约束，不单靠上调拖载奖励或削弱旧能力保护。先检查教师已能实现的行为能否在部署观测下被学生表达，再做单因素奖励试验。

## 6. 完整路线验收

`protocol_v7.py` 在旧16项基础上加入 **−20°/40 kg静止和移动制动**，得到18边界项；全条件覆盖64许可条件×静止/移动=128项。保持旧速度、姿态、航向、支撑、漂移、碰撞和完整保持窗口阈值。拖载额外检查真实拖车净进度达到1 m，不能仅用机器人拉伸拖杆的位移替代。

现有距离命令仍以机器人1 m触发减速；如果拖车未走够1 m，新检查会判失败，不能自动放宽为通过。后续若改为机器人/拖车较慢者触发，必须独立修改命令契约并重建统一Actor基线。

正式最终验收还需独立初态扰动和多种子；当前 `evaluate` 命令只执行指定清单的冻结初筛，不代表硬件验收或所有扰动已覆盖。持续电机负荷与硬件选择放在行为通过之后。
