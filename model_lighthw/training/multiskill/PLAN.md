## 2. 命名、共享与隔离

新逻辑编号放在 `training/multiskill/routes/route_00_baseline_reference`、`route_01_wheel_locomotion` 等。
运行源码只放 `source/rl_training/rl_training/tasks/manager_based/locomotion/multiskill/lighthw/`。
注册是显式调用，导入新包不会自动注册任务；只注册真正实现的 Route01 Stage1。
manifest 中规划项目的 task_id 为 null，启动器拒绝启动。

共享模块提供：路线索引、每次运行独立路径、来源记录、训练/回放/评估入口和固定评估协议。
任务差异集中在环境子类及独立奖励配置。Route01 从 Rough 环境继承场景和本体观测，
在自己的实例中换为平地、自己的奖励、重置和命令；不修改公共配置。
每个 run 保存 console、状态、seed、预算、有效 YAML、代码/URDF/mesh 哈希与源码快照；
训练、短验、评估、播放分别建独立时间戳目录，USD 转换缓存也归本 run。
旧 checkpoint 不自动搜索、不恢复、不覆盖；本轮训练入口仅支持从零。
后续恢复必须验证动作/观测版本、优化器、归一化和 Actor 类，不能只检查张量形状。

## 4. Route01 本轮可实现范围

只实现 Stage1：平地、空载、无牵引、前进 .2～.6m/s、25%显式零指令、8秒重采样。
维持12腿位置+4轮速；使用原生线性目标映射，腿scale .08/.14、clip规范URDF限位，轮5/37。
复用当前已使用的1kHz物理/50Hz策略、默认高度.416/出生.430、腿PD80/3、轮damping1、无延迟。
这些是新实例的独立设置，公共资产与旧训练数值保持。与旧Rough40/42有明确区别，不做旧模型直接恢复。

Actor=57：角速度3+重力投影3+指令3+关节相对角16（4轮角置零）+关节速度16+上一动作16。
删除仿真线速度和高度真值；Critic=236，保留线速度与176维height_scan。
IMU角速度、姿态估计的重力方向、编码器、指令和上一动作有实机获取路径；
仍需校准坐标系/延迟/噪声，不能据此宣布已部署。没有接触传感器时不向Actor直接喂真值接触。
当前不是RNN且不堆叠历史；若坡地/打滑可观测性不足，另版本加入历史或经验证的速度/接触估计器。
57维与历史60维策略不兼容；这是独立从零的工程基线，不宣称优于现有策略。

奖励单独定义：平面速度/偏航跟踪；姿态和高度；腿力矩/动作变化/关节限位；
零指令下机身平速/角速、轮速、默认腿姿、四轮支撑；运动时站立专用项返回0。
Stage1平地姿态/高度项以后不能原样用于坡地，应按地形法向/相对高度重新设计。
跌倒/非轮碰撞单独终止并计数。无自动课程晋级、自动续训、额外加载或模型选择。

## 5. 课程与晋级（后续开发，不伪装成已实现）

Route01：S1平地空载低速起停 → S2逐段.6/1/2/3m/s与制动 → S3±5°低坡 →
S4±10/15/20/25° → S5载荷0/5/10/15kg、测定牵引模型 → S6组合工况与多seed。
坡度必须用 `tan(angle)` 转换；本地 IsaacLab `hf_terrains.py` 明确 slope 是高差/水平距离。
旧0～.25仅到约14.04°，25°对应约.4663；含坡地配置不等于已学会坡地。
先固定5°上/下坡测速度误差、侧滑/姿态、轮接触、制动，再决定高度观测/历史改动。
不能把拖动40kg等同于施加40kg重力：需牵引点、被拖体滚阻/坡度、惯性和绳索模型。

02A：低速交替抬腿 → 接触节律 → 速度/负载/牵引；02B：单阶3/6/10/13/16cm →
280mm踏面连续上/下阶 → 加载。上阶和下阶分别统计；台阶几何不能用总爬升替代单阶高度。
03：可达/接触规划 → 无载低平台 → 分阶段支撑转移 → 下落 → 10kg/800mm组合。
04：四轮保持 → 前/后重心转移 → 短双支撑 → 延时/扰动 → 返回四轮。
05A/B：驱动/弹跳可行 → 参考轨迹或模仿候选 → 起跳 → 空中旋转 → 落地缓冲 → 连续稳定。
06：结构与静力学通过 → 无载稳定 → 小幅缓加载 → 载荷扰动 → 分级到65kg并做持续热约束。

晋级先使用固定协议、至少3个评估seed/多个reset，任务成功率≥95%、无NaN/Inf、无非法碰撞，
并达到该阶段速度、姿态、保持及饱和指标；具体阈值见各任务评估协议。
这些是候选工程门槛，应在采集基线后锁定，不能为了通过回头改阈值。
本轮Stage1评估只给技能筛查结果，最终验收字段始终为“未评估”。

## 6. 硬件可行性初审

本地规范URDF总质量约11.6681kg；大腿/小腿关节到下一轴的z长度约.21/.25m，轮半径注释约.0875m。
hip限位±.4rad；前腿和RL thigh为[-2.6952,1.5613]，RR为[-1.5613,2.6952]；calf±2.5。
腿模型上限48Nm/12.57rad/s，轮24Nm/37.7rad/s。这些是模型参数，不能当作实机持续输出证明。
轮目标37rad/s对应理想无滑动约3.24m/s，3m/s余量很小；负载/坡地会改变所需力矩与滑移。
基础资产关闭自碰撞；高动态前必须验证碰撞网格与自碰撞，不在本轮修改公共开关。

800mm高于.46m两段腿的长度尺度；这不单独证明整个攀爬不可能（身体转动、分阶段接触会改变几何）。
还缺后备箱边缘/开口/踏面、允许接触区、完整FK/IK碰撞扫掠、可行支撑域和力矩-速度曲线。
需解各阶段接触约束、质心投影/动态稳定及 `tau=J^T f`，再决定机械可行或明确不可达。
不能靠奖励权重给出“800mm已可攀爬”的结论。

空载+65kg约76.67kg，总重约752.1N，理想均摊每腿188.0N；真实接触分配和力臂决定关节矩，
均摊载荷不是结构/电机通过证明。静态65kg不等于所有腿都只承受四分之一；倾斜和扰动会重新分配。
15kg载荷需同步建模附加质量、质心和转动惯量；不是只增重而不改惯量。
后/侧空翻需要角动量、起跳冲量、能量、速度限制、接触冲击和落地行程计算；目前缺电机持续/峰值曲线、
减速器效率、热/电池/结构约束、载荷固定位置。以上均列为未决，暂不注册训练环境。

补充：本轮已按实际默认角/碰撞mesh完成纯CPU的FK、质心和理想静载计算，
见 [模型初审](records/MODEL_AUDIT.md) 与可复算JSON。默认质心相对Base_link约
(20.898,-0.806,-85.652)mm，四轮接触范围约x[-.3411,.3336]/y[-.2024,.2024]m。
假设载荷质心(0,0,.20)m、四轮理想竖直力分配，65kg示例最大腿静矩约36.423Nm；
这不是持续力矩、结构、动力学或硬件承载证明，尚不据此注册65kg训练。

## 7. 评估与技能管理接口

Route01固定零命令、.3/.6起步-巡航-停车，默认评估seed43/44/45，训练seed42。

目标裁剪饱和、跌倒/终止、载荷0kg/牵引0N、seed；不以Mean Reward判成功。

超时/提前终止必须按失败记录，不能自动重置后把出生帧算成功。训练和评估输出严格分开。

未来每个Actor交付 manifest：观测/动作版本、顺序/缩放/频率、适用速度/坡度/载荷、
进入/退出条件、目标姿态/模式、checkpoint哈希、有效评估记录及回退方式。
预留 Task Command → Skill Manager → Actor Selector → Action Transition → Joint Controller。
