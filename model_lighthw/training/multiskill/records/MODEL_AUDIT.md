# LightHW 模型几何与静载初审

2026-10-15，纯CPU计算，使用当前canonical URDF、17个collision STL和实际默认关节角。
来源/完整数值：[model_audit.json](model_audit.json)。复算入口：`python model_lighthw/training/multiskill/audit_model.py`。
复用既有 `scripts/tools/lighthw_standing_pose.py` 的URDF齐次变换与STL读取，没有运行该旧工具的改姿态流程。

四轮支撑时默认质心投影在四接触点形成的区域内。前/后两轮各自的接触点近似组成一条横向支撑线，
默认质心不在这两条线上，因此不能只把两条腿抬起就假定完成静态双腿平衡；需要身体/腿姿变化、
有限接触面的验证和动态平衡。800mm高于水平机身/hip=0站高上界，但多阶段攀爬会改变身体姿态，
本计算不能据此判定整个任务绝对不可能。完整碰撞约束下的可达空间扫描尚未完成。

静载示例固定当前水平默认姿态，假设附加载荷质心在Base_link坐标(0,0,0.20)m。
解四轮竖直接触力的总力与两个力矩平衡，采用最小范数解；四个力均为非负。
对每个腿关节计算其子树重力和轮接触力的轴向力矩，等价于该静态接触条件下的J转置力映射。

| 附加载荷 | 12个腿关节中最大静态力矩绝对值 |
|---|---:|
| 0kg | 4.857Nm |
| 10kg | 9.713Nm |
| 15kg | 12.141Nm |
| 65kg | 36.423Nm |

**这不构成65kg硬件承载通过。** 36.4Nm低于模型48Nm裁剪值，只说明上述理想静态分配未超过该模型值。
持续电机/减速器/结构/热能力、真实载荷位置、力分配、姿态偏差和冲击均未验证；
48Nm不能当作实际持续额定值。这里只计算轮的竖直支撑，不模拟牵引、坡地摩擦和轮地冲击。
载荷示例没有修改URDF或新增加载事件，不是负载仿真试验。Route03/05/06仍保持可行性待定。
